DraftToBlog

把飞书导出的 Markdown 工作草稿，自动完成图片上云、博客化重构与隐私脱敏，一键生成可公开分享的标准化博客网页。

0 裂图 本地图片自动迁移为 HTTPS 外链
可核对 脱敏记录可视化，降低泄密风险

产品定位

DraftToBlog 面向职场人、开发者和内容创作者，专注解决“工作文档无法顺手变成公开博客”的问题。它不破坏原始文件，而是输出一份适合公开传播的新文档与网页。

图片资源孤岛

飞书导出的 Markdown 图片多为本地绝对路径或缓存路径，发布到博客后容易全部裂图。

内容形态不匹配

工作记录常是流水账、备忘录和台账，缺少公开博客需要的引导、层次和教学逻辑。

隐私泄露风险

文档中常混有公司名称、项目代号、账号、内网地址和未公开业务信息，手动脱敏容易遗漏。

三大核心能力

围绕“能不能发、好不好读、安不安全”三个关键问题，DraftToBlog 将文档发布流程压缩成一次上传和一次确认。

1

图片云端迁移

批量解析 Markdown 中的本地图片路径，自动上传到云图床，并将全文链接替换为可公开访问的 HTTPS 地址。

2

博客化重构

自动补全引言、重排章节、润色语句、统一标题与代码块格式，让内部记录变成教程式分享文章。

3

智能脱敏过滤

识别公司、项目、人名、手机号、账号、内网地址等敏感内容，支持替换、整行过滤和脱敏日志核对。

完整闭环

从工作场景中的飞书文档开始，到公开可访问的博客网页结束，工具承担中间重复、繁琐且有风险的转换工作。

用户与场景

核心用户

需要沉淀工作经验的开发者、产品经理、运营同学、技术写作者、知识管理爱好者，以及经常从飞书整理资料的团队成员。

典型场景

项目复盘、问题排查记录、工具教程、学习笔记、流程文档、经验分享等内容完成后，希望快速转成可公开传播的博客页面。

价值与意义

DraftToBlog 的价值不是简单“格式转换”，而是把工作产出转化为个人知识资产：更高效、更安全，也更适合长期沉淀与公开分享。
